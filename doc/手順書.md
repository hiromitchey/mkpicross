MVP（Step 1〜4）で「自分で作って遊べる」状態まで仕上げ、v1（Step 5〜9）で一般公開。スターターには各Stepの土台が入っているため、「未」の部分を足していく進め方。

## 1. スターターを動かす

```bash

git init && git add -A && git commit -m "starter"
pnpm install

```

`apps/web/.env.local` に値を記入。開発時の Next.js は `apps/web` の `.env.local` を読む（ルートの `.env` は Step 9 の Docker Compose 用）。

## 2. 共通ロジック（packages/core）

ブラウザ（プレビュー・Worker）とサーバー（再検証）で同じコードを使う中核部分。完成済み、調整のみ。

| ファイル | 役割 | 主な関数 |
|---|---|---|
| types.ts | 盤面の型。0 = 未確定、1 = 黒、2 = 白 | `createGrid` |
| clues.ts | ヒント生成、正解判定（ヒント充足） | `computeClues`, `isSolved`, `satisfiedLines` |
| encode.ts | 盤面 ⇔ 行優先ビット列のbase64 | `encodeBits`, `decodeBits` |
| lineSolver.ts | 1列のライン解法（動的計画法） | `solveLine` |
| solver.ts | ライン解法 → 仮置き → 分岐探索、公開判定、難易度 | `solve`, `isPublishable`, `estimateDifficulty` |
| uniquify.ts | 未確定マスの開示で一意化、別解との差分 | `suggestGivens`, `diffCells` |
| convert.ts | 画像 → 白黒グリッド（設計書4章の3〜8段） | `convertImage`, `otsuThreshold`, `DEFAULT_PARAMS` |

```ts
import { computeClues, convertImage, DEFAULT_PARAMS, isPublishable, solve, suggestGivens } from "@picross/core";

const { grid } = convertImage(imageData, { ...DEFAULT_PARAMS, gridWidth: 20, gridHeight: 15 });
const result = solve(computeClues(grid), { search: false }); // 公開判定だけなら分岐探索なし
if (!isPublishable(result)) {
  const { givens, solvable } = suggestGivens(grid); // 未確定マスを開示して一意化
}
```

調整ポイント:

- `estimateDifficulty` の係数: 実際に遊んで★の感覚に合わせる
- `suggestGivens` の `maxGivens`（既定20）: 超えたら絵の修正を促す
- `DEFAULT_PARAMS`: 既定のコントラスト1.5など

変更したら `pnpm test`。新しい変換モードを足すときは「既知の画像 → 期待するグリッド」のテストを1件追加。

## 3. MVP: 作者画面を仕上げる

スターター済み: 画像読み込み（グリッドの縦横比で中央を自動切り抜き、最大辺1024px）、幅・高さ・コントラスト・明るさ・反転・孤立点除去、クリックで白黒反転、Web Worker での検証、未確定マス（赤枠）・開示マス（青枠）表示、開示マスで一意化、画像保存（送信前にブラウザで最大辺2048pxへ縮小）、JSON書き出し、時間切れ・保存失敗のエラー表示。

| # | 作業 | 実装メモ |
|---|---|---|
| 3-1 | トリミングUI | `react-easy-crop`（6.2系）で切り抜き枠を指定、縦横比 = 幅:高さ。得た `croppedAreaPixels` を `AuthorTool.tsx` の `loadImage()` の `drawImage` 引数（sx, sy, sw, sh）へ |
| 3-2 | パラメータ追加 | ガンマ、しきい値方式（大津法 / 固定）、固定しきい値のスライダー。`ConvertParams` 側は対応済み |
| 3-3 | 3面プレビュー | 元画像・グレースケール（`adjust(toGray(img), params)` を canvas に描画）・ドット結果 |
| 3-4 | ドット編集の強化 | PlayBoard と同じドラッグ塗り（行・列に固定）、Undo/Redo、元画像の半透明重ね（SVG の `<image>` に opacity 0.3） |
| 3-5 | 線画モード | `convert.ts` に `mode: "fill" \| "line"` を追加。Sobel で輪郭 → 3×3で太らせる → 面積平均で縮小 → しきい値。テスト追加 |
| 3-6 | 警告表示 | 黒率30%未満・70%超、空行・空列が3割超 |
| 3-7 | テストプレイ | `PlayBoard` に `onSolved` を追加し、判定APIを使わずローカル判定で遊べるように |
| 3-8 | 下書き自動保存 | パラメータ・グリッド・開示マスを localStorage に |

### MVPでの問題の追加手順

1. `/author` で画像読み込み → 調整 → 検証 →（未確定マスがあれば）手修正か「開示マスで一意化」→ タイトル入力 → JSON書き出し
2. 書き出したJSONを `apps/web/data/puzzles/` に配置
3. 元イラストを `apps/web/public/mvp-images/` に置き、JSONの `image` をそのファイル名に（MVPでは「画像を保存」は押さない。押すと `image` が保存キーになる）
4. `pnpm dev` を再起動 → `/play/<id>`

MVPは元イラストを `public/` に置くため、URLを知っていれば解く前に見られる状態。ローカル用と割り切り、ネタバレ対策は Step 5 で有効化。

## 5. v1: DB（PostgreSQL＋Drizzle）

スターター済み: `db/schema.ts`、`db/client.ts`、`drizzle/0000_init.sql`、`lib/puzzleRepo.ts`（取得・一覧・判定用取得・非公開化）、`POST /api/author/puzzles`（作成。サーバーでヒント・検証を計算し直し）、`POST /api/author/puzzles/[id]/publish`（再検証 → 公開 → キャッシュ破棄）。

```bash
# 1. ローカルに PostgreSQL
docker run -d --name picross-db -p 5432:5432 \
  -e POSTGRES_USER=picross -e POSTGRES_PASSWORD=picross -e POSTGRES_DB=picross postgres:17

# 2. マイグレーション
export DATABASE_URL=postgres://picross:picross@localhost:5432/picross
pnpm db:migrate

# 3. 作者ユーザー（admin）を1件
docker exec -it picross-db psql -U picross -c "insert into users (display_name, role) values ('運営', 'admin');"

# 4. プレイ画面・判定API・OGP を DB 版に差し替え、クリア済み再表示API（reveal）を追加
cp v1-swap/play-page.tsx       "apps/web/app/play/[id]/page.tsx"
cp v1-swap/verify-route.ts     "apps/web/app/api/puzzles/[id]/verify/route.ts"
mkdir -p "apps/web/app/api/puzzles/[id]/reveal"
cp v1-swap/reveal-route.ts     "apps/web/app/api/puzzles/[id]/reveal/route.ts"
cp v1-swap/opengraph-image.tsx "apps/web/app/play/[id]/opengraph-image.tsx"
```

5. `apps/web/.env.local` に `DATABASE_URL` と `STORAGE_DIR=./storage` を追加して `pnpm dev` を再起動

差し替え後の要点:

- プレイ画面はビルド時に問題IDが分からないため、`params` を `<Suspense>` の内側で読む形（Next.js 16 の Cache Components の要件）
- 問題データは `"use cache"`＋`cacheTag("puzzle-<id>")` でキャッシュ。公開・非公開化で `revalidateTag(tag, { expire: 0 })` により即時破棄
- 存在しないIDは「見つかりません」表示。ストリーミングの都合でステータスは200

| # | 作業 | 実装メモ |
|---|---|---|
| 5-1 | 作者画面から保存・公開 | 「画像を保存」→ `imageKey`。「下書き保存」で `POST /api/author/puzzles`（title, width, height, `solution = encodeBits(grid)`, givens, convertParams, imageKey）。返った id で「公開」→ `POST /api/author/puzzles/{id}/publish` |
| 5-2 | 作品管理画面（A7） | `/author/puzzles`: 一覧、非公開化（`hidePuzzle`）、プレイ数・クリア率 |
| 5-3 | 一覧ページのDB化 | `listPublishedDb()`（タグ `puzzle-list` でキャッシュ済み） |
| 5-4 | 版の更新（PUT） | 新しい版を insert → `current_version` 更新 → キャッシュ破棄。公開後の編集を許すかは設計書15章の未決事項 |

スキーマ変更時: `db/schema.ts` 編集 → `pnpm db:generate` → `drizzle/` をコミット → `pnpm db:migrate`。

完了条件: 作者画面から作成 → 公開 → `/play/<uuid>` で遊んでクリア → 元イラスト表示。

## 6. v1: 判定・画像・ヒントAPI

スターター済み（Step 5 の差し替え後）: verify（署名付き画像URL＋クリアトークン）、reveal（トークンから画像URLを再発行）、`GET /api/images/[key]`（署名・期限チェック）、`POST /api/author/images`（sharp で回転適用 → 最大辺1600px → WebP。EXIFはここで消える）。

| # | 作業 | 実装メモ |
|---|---|---|
| 6-1 | クリア済みの再表示 | プレイ画面の表示時に localStorage のクリアトークンがあれば `POST /reveal` → 元イラストを表示 |
| 6-2 | ヒント（`POST /api/puzzles/{id}/hint`） | 入力: 版、塗りと×の盤面（`encodeBits` を2本）。解答と食い違うか未入力のマスを1つ返す `{x, y, state}`。使用回数はクリア画面に表示 |
| 6-3 | 答え合わせ（`/check`） | 間違いマスの「数」だけ返す（位置は返さない）。1問あたりの回数制限 |
| 6-4 | 通報（`/report`） | `reports` に insert。理由は選択式（権利侵害 / 不適切 / その他）＋自由記述500字まで |
| 6-5 | プレイ数・クリア数 | 初回表示と verify 成功時に加算。同一端末の重複はクリアトークンの有無で抑制 |

レート制限はアプリ側に持たず、Step 9 の Traefik で掛ける。

## 9. VPSへデプロイ（Docker＋Traefik）

Dockerfile と compose.yaml は同梱済み。Dockerfile と同じファイル配置で standalone サーバーの起動までは確認済みだが、Docker でのビルドと Traefik 連携は未実施。初回はビルドログとTraefikのダッシュボードで確認。

```bash
# VPS 上で
git clone <リポジトリ> picross && cd picross
cp .env.example .env
#  SITE_URL=https://picross.example.com
#  署名鍵3つは本番用に新しく生成、AUTHOR_PASSWORD、POSTGRES_PASSWORD
#  （DATABASE_URL と STORAGE_DIR は compose.yaml 側で上書き）
```

`compose.yaml` のラベルを既存のTraefik設定に合わせて編集: ドメイン（`picross.example.com`）、entrypoint名（`websecure`）、certresolver名（`le`）、外部ネットワーク名（`traefik`）。

```bash
docker compose build
docker compose up -d db
docker compose run --rm migrate
docker compose exec db psql -U picross -c "insert into users (display_name, role) values ('運営', 'admin');"
docker compose up -d web
```

動作確認:

```bash
D=https://picross.example.com
curl -sI $D/author | head -3                                   # 307 → /author/login
curl -s -o /dev/null -w "%{http_code}\n" $D/api/images/x.webp  # 403
for i in $(seq 1 30); do curl -s -o /dev/null -w "%{http_code} " -X POST $D/api/puzzles/<id>/verify -d '{}'; done
#  途中から 429（レート制限が効いている）
```

更新デプロイ:

```bash
git pull
docker compose run --rm migrate   # スキーマ変更があるときだけ
docker compose build web && docker compose up -d web
```

Vercel を使う場合: `lib/storage.ts` の3関数を S3互換（Cloudflare R2）版に差し替え（保存は `@aws-sdk/client-s3`、期限付きURLは `@aws-sdk/s3-request-presigner`）、レート制限は Traefik 以外の手段、`output: "standalone"` は不要。

## 11. 運用

| 作業 | 手順 |
|---|---|
| 問題の追加 | `/author` → 画像 → 調整 → 検証 → 下書き保存 → 公開 |

## 付録A: 落とし穴と対処（検証中に実際に遭遇したもの）

スターターはすべて対応済み。ゼロから組む場合や、Next.js を更新したときの参考。

| 症状 | 原因 | 対処 |
|---|---|---|
| `@picross/core@workspace:*` が見つからない | create-next-app が `apps/web` に独自の `pnpm-workspace.yaml` と lock を作る | それらと `apps/web/node_modules` を削除し、ルートの `pnpm-workspace.yaml` に統合 |
| ビルドで Google Fonts の取得に失敗 | 初期テンプレートの Geist（日本語なし）を `next/font/google` で取得 | `layout.tsx` から `next/font` を外してシステムフォントに。日本語Webフォントが要るなら `next/font/local` |
| `Uncached data was accessed outside of <Suspense>` | Next.js 16 の Cache Components（初期設定で有効） | データ取得関数に `"use cache"`＋`cacheTag`。ビルド時にIDが分からないページは `params` を `<Suspense>` の内側で読む |
| `revalidateTag` の第2引数がない警告 | Next.js 16 で第2引数が必須化 | 即時反映は `revalidateTag(tag, { expire: 0 })` |
| `middleware.ts` が非推奨 | Next.js 16 で `proxy.ts` に改名（Node.js 実行が既定） | `proxy.ts` に `export function proxy` |
| ログイン後に `localhost:3000` へ飛ぶ | Route Handler で `req.url` から組んだURLが、standalone 実行では内部ホスト名になる | `new URL(path, process.env.SITE_URL)` で組み立て |
| ビルド警告「Dynamic filesystem access causes tracing of the whole project」 | 実行時に決まる保存先パスへのファイルアクセス | 該当の呼び出しに `/*turbopackIgnore: true*/` |
| standalone でCSS・JSが404 | standalone 出力に `.next/static` が含まれない | Dockerfile で `.next/static` と `public` をコピー |
| モノレポで standalone に依存が足りない | ファイル追跡の起点が `apps/web` | `outputFileTracingRoot` をリポジトリのルートに |
| tsx でスクリプト実行時「Top-level await is currently not supported with the cjs output format」 | `apps/web` が `"type": "module"` でない | スクリプトの拡張子を `.mts` に |
| ノイズの多い画像で検証が終わらない | 分岐探索は最悪で指数時間 | 公開判定はライン解法＋仮置きのみ。分岐探索は参考情報で3秒打ち切り |
| 開発モードで再読み込みすると途中保存が消える | React の StrictMode は副作用を2回実行する。「復元」より先に「保存」が走ると空の盤面で上書きされる | プレイヤーが操作するまで保存しない（PlayBoard の `dirty`） |
| 盤面の外でボタンを離すと、戻ってきたときに勝手に塗られる | 盤面の外では pointerup を受け取れず、ドラッグ状態が残る | pointerdown で `setPointerCapture` |
| 別の問題へ移動しても前の盤面が残る | 同じ位置の部品は React が状態を引き継ぐ | `<PlayBoard key={問題ID:版}>` で作り直す |
| サーバーを止めたのにポートが使用中 | Next.js のプロセス名が `next-server` に変わる | `pgrep -f "^next-server"` で探して停止 |
