## 開発環境

- WSL に Node / pnpm は入れず、Docker で回す（`compose.dev.yaml`）
  - 起動: `docker compose -f compose.dev.yaml up -d` → http://localhost:3000
  - テスト: `docker compose -f compose.dev.yaml run --rm web pnpm test`
  - lint: `docker compose -f compose.dev.yaml run --rm web pnpm --filter web lint`
  - 停止: `docker compose -f compose.dev.yaml down`
- 署名鍵と作者パスワードは `apps/web/.env.local`（Git 対象外）

## いま動くもの

- `/`: 画像 → ドット変換ツール（`apps/web/components/PixelTool.tsx`）
  - 読み込み: ドロップ、ファイル選択、Ctrl+V で貼り付け
  - 切り抜き: 枠をドラッグで移動、「拡大」で範囲を絞る（縦横比はマス数に連動）
  - マス数: 幅・高さ 5〜30、正方形のプリセット
  - 変換のしかた: 「濃淡で変換」（明るさで白黒）と「シルエット」（透過していない所を色に関係なく黒）。背景が抜いてある画像は自動でシルエットになる
  - 調整: コントラスト、明るさ、ガンマ（濃淡のみ）、しきい値（自動 / 手動。シルエットの自動は 128 = マスの半分以上が不透明なら黒）、白黒反転、孤立点除去
  - 手修正: クリックで反転、ドラッグで連続塗り、戻す / やり直す（Ctrl+Z / Ctrl+Y）。スライダーを動かしても残る
  - 表示: 元画像の重ね表示、マス目の切替、調整後の濃淡プレビュー
  - 書き出し: PNG（1マス 1 / 8 / 16 / 32px）、■□ のテキストをコピー
- 変換本体は `packages/core/src/convert.ts`（グレースケール → 階調調整 → 大津法 → 面積平均で縮小 → 二値化 → 孤立点除去。シルエットは透明度をそのまま濃淡として使う）
  - ピクロスにして送る（`components/SharePanel.tsx`）: 答えが1つに決まるか確認し、必要なら初期開示マスを選んで、共有 URL `/p#<8文字の ID>` を作る
- `/p`: 共有されたピクロスを解く画面（`components/SharedPlay.tsx`）。解くと「おめでとう」→ 元の絵が浮かび上がる
  - 仕組み（`lib/share.ts`）: ヒント・初期開示マス・題名と、**答えの盤面を鍵にして AES-GCM で暗号化した元の絵**（最大辺 256px の WebP）を圧縮して「共有コード」にする。答えのドット絵そのものは入れない
  - 共有コードはサーバーの `STORAGE_DIR/shares/<id>.txt` に預ける（`lib/shareStore.ts`、`/api/shares`）。DB は使わない。サーバーにあるのは暗号化済みの絵だけ
  - 限界: ヒントから答えは計算できるので、ソルバーを使えば解かずに絵を開けられる。友だち同士で遊ぶための目隠しと割り切る
- `/author`: 元からある作者ツール（ピクロスとしての検証・JSON 書き出し。ログインが必要）
- `/play/heart`: サンプル問題のプレイ
